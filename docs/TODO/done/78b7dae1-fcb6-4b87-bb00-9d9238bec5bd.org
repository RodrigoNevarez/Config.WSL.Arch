#+TITLE: Use WSL-native npm instead of Windows npm
#+DATE: 2026-08-12

* Problem

Inside the Arch WSL shell, =npm= resolves to the Windows install via
interop instead of the nvm-managed WSL npm:

#+begin_src sh
[root@rodris arch]# which npm
/mnt/c/Program Files/nodejs/npm
#+end_src

This happens because WSL's interop PATH (=/mnt/c/...=) is ahead of the
nvm path, or nvm isn't loaded in the shell at all. As a result, global
npm installs (e.g. =claude-code=) land in the Windows npm prefix
(=C:\Users\rodri\AppData\Roaming\npm=) instead of inside WSL.

- [ ] Best fix: stop Windows binaries from leaking into WSL's PATH.
  Edit (or create) =/etc/wsl.conf=:
  #+begin_src conf
  [interop]
  appendWindowsPath = false
  #+end_src
  Then, from PowerShell (outside WSL): =wsl --shutdown=, then reopen
  the Arch terminal.

  *Caveat:* this also hides other Windows tools (git.exe, code.exe,
  etc.) from WSL shells — only do this if those aren't needed from
  within WSL, or re-add specific ones to PATH manually.
